# 验收与评审循环

**做的人不评自己的作品。** 没有 bug 不等于做完；能和参考作品摆在一起不露怯才算做完。

## 一、质量线（qa.py 全量化）

```bash
python3 scripts/qa.py <工程>      # → qa/qa_report.md、out/抽帧_每秒2帧.jpg、out/抽帧_16帧.jpg
```

| 项 | 线 | 怎么量 |
|---|---|---|
| 时长（视频流帧数） | 视频流帧数＝时间线帧数 | ffprobe 数帧（容器时长会被音轨撑长，不可信） |
| 尺寸／帧率 | 1080×1920；30fps | ffprobe |
| 第一帧 | 是完成画面（非黑、有字有图） | 第 0 帧亮度与边缘密度 |
| 冻结 | 任何静止段 ≤0.5s | **只量画面窗**；信息卡镜头量讲解人框（K 包）或卡片以外的画面窗（A／B／C），K 包大字卡扣掉卡面（几何在 layout.json）；（分带刊物排除纸面，满幅版式排除下部字幕区）；270×480 灰度相邻帧均差 <0.35 的连续段。大字卡最容易犯：字落定后底层要自己在动（匀速推＋她的动作透出来），见 07 #46 |
| 响度／真峰值 | −14 ±1 LUFS／≤ −1 dBTP | ebur128 |
| 配乐不糊人声 | 人声频带高出配乐：低 10% ≥12 dB | mix.py 量好写进 qa/audio.json |
| 字幕对位 | **字完整可读的那一帧**比开口早 ≤6 帧、晚 ≤1 帧；全片字晚于声音合计 0s | 有入场的卡按动画做完那一帧算，不按动画起点（第 1 轮评审指出旧量法是假通过） |
| 口型 | 剪后画面与人声同长，差 ≤1 帧 | 同一张 EDL 按帧剪 |
| 字幕停留 | 每句连续显示 ≥0.7s（被剪辑点切开的同一句合起来算） | timing.json |
| 大字卡完整可读 | 字落下后到下一镜 ≥1.3s | timing.json（不量在屏时长） |
| 人脸碎片 | 镜头之间、跳切之后 ≤6 帧的人脸为 0 | timing.json＋edl |
| 画面窗空白帧 | 0（≥85% 的行是平的亮纸色＝闪白） | 成片逐帧 |
| 对比度（理论） | 底板下面是纯白时 ≥4.5:1 | 按底板透明度算 |
| 对比度（实测） | 成片帧上字所在区域的底 vs 字色 ≥4.5:1 | 分带刊物量文字带的纸；满幅版式量底板内边距或雾 |
| 安全区 | 字幕右沿 ≤940 | 按字数估宽 |
| 屏上文字出处 | 刊头、封面（含数字／对比／原话形式）、名字条、标注、大字、下期预告每一条在 facts.json 有原句；**每张信息卡在 facts.cards 登记一次** | 精确比对 |
| 账号主题对比度 | 纸上强调字对纸 ≥4.5:1；页脚对平台白字 ≥12:1 | timeline.theme 按 WCAG 算 |
| 节奏 | 人脸同一景别 ≤8.5s；B 单条 1.6–6.5s；人脸占比 35–60% | timing.json |
| 近空画面 | 0 处 | qa_edge.py（`--abs 0.016`，已复制进本 skill） |
| B-roll 重复帧 | 0 | 成片里每个 B／S 镜逐帧比，相邻两帧完全一样计 1（24/25fps 素材时间基没改对会每 5–6 帧重复 1 帧，第 4 轮评审实测） |
| B-roll 内部亮度跳变 | 0 | 每条归一化片段逐帧均亮，一帧跳 ≥5 级且前后平稳＝素材自带的自动曝光跳（第 5 轮：走廊「闪了两下」） |
| 片尾杂音 | 最后一个字后人声轨峰值 ≤ −35 dBFS | voice_cut.wav 从最后一个字的字尾量到结尾（第 4 轮：她伸手点手机的咔哒声） |

另有两张图给人看：`out/抽帧_每秒2帧.jpg`（静音解读）、`qa/接缝检查.jpg`（`seams.py`：每个剪辑点前后 8 帧，含切点本帧，看交接有没有闪、叠、空）。落版段按设计是停帧缓推，冻结检查对它豁免。

## 二、评审循环（照 brief 的要求）

每次整片渲染后，派一个**全新的评审子代理**（它没看过制作过程）。评审提示词模板见下；它自己抽帧、自己量。
按严重程度修：先修最大的，重渲，再派一个新评审把**之前所有项**重查一遍。每一轮记进 `ledger.md`：改了什么、改前数字、改后数字、谁评的。

评审提示词模板（把尖括号换掉）：
```
你是一名独立评审（动效导演＋剪辑指导），没有参与这支片子的制作，只看成品和数据。不要改任何文件。
成片：<out/成片_9x16.mp4>　原片：<原始口播>　时间真源：<timing.json>　镜头计划：<decompose.json>　出处：<facts.json>　逐字稿：<work/transcript_cut.json>
上一轮报告：<qa/评审_第N-1轮.md>（逐条复核：已解决／部分／未解决）　自动验收：<qa/qa_report.md>　接缝图：<qa/接缝检查.jpg>
参考作品：<参考成片路径>（对标结构与完成度，不要求画面一样）
1. 静音解读：只看每秒 2 帧的无声拼版，复述故事（谁、在哪、讲了几件事、结尾要我做什么）。读不出来的指出来。
2. 逐帧抽查：每 0.2 秒一帧通看；每个剪辑点前后 ±6 帧逐帧看。找字幕与剪辑不同步、字压脸／压进右侧互动栏、看不清、一闪而过、画面与话不搭、裁切发糊、断行难读、包装件互相打架。
3. 对标：参考片与成片各抽 10 帧并排，判断放进同一条信息流会不会更弱。
4. 事实核查：屏上每句非口播文字在 facts.json 有没有出处、转述有没有改原意。
5. 导演审片：毫不留情地指出拼凑、拖沓、平庸、像模板的地方。
报告写到 <qa/评审_第N轮.md>：静音解读／问题清单（P0 必改、P1 应改、P2 可更好；每条：时间码、现象、量到的证据、改法）／对标结论（三句话）／结论「可以发布」或「再改一轮」。
```

## 三、只有人能判断的（交付说明里必须列出来，让用户亲眼看、亲耳听）

1. **剪口癖的切点**：⚠ 标的几处要戴耳机听一遍，有没有吞字、气口是否自然。
2. **校对里标了「待确认」的字**（人名、学制、数字）——ASR 和语境都可能错。
3. **B-roll 有没有误导**：示意画面会不会被当成「她本人／她孩子的学校」；**画面里任何可读的数字、班号、招牌、校名都要和屏上的事实一致**（第 5 轮：「4-1 Classroom」班牌配「中五」）。
4. **配乐好不好听、情绪对不对**：指标只能保证不糊人声。
5. **肤色与调色**：原片如果是 iPhone HDR，转 SDR 后人脸颜色要看一眼。
6. **合规**：理财类口播里的收益、产品、承诺性说法，发布前过 `dbs-content-risk-check` 与公司合规。
