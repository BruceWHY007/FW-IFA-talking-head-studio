# 12 · 极简档与完整版（10-30 重定）

## 两档差在哪（一句话）
**差在谁来判断、谁挑素材、谁来审——不差信息量。完整版 ≥ 极简档。**

10-30 之前这里写的是「极简档只用满幅、人脸 85–90%」，DeepSeek 按字面理解成「镜头少」，又反过来把完整版也做成了那样（完整版连金银整行都没有）。现在两档用同一份自动底稿：

| | 极简档 | 完整版 |
|---|---|---|
| 分镜从哪来 | `lite_plan.py` 自动出 `decompose_lite.json`，Agent 只改 `_待改`（自动摘的文字读顺） | `lite_plan.py --full` 出同一份底稿 → Agent 逐条做完 `_待升级` |
| 两档都有 | 数字卡 G、步骤标题＋进度坞、堆叠清单、清单卡 I list（问题清单用皱纸单）、金银整行、关键词变金、满幅 B-roll（每 14 秒一条，人脸 ≤80%） | 同左 |
| 只有完整版有 | — | 小窗／光晕圆／细环／分带／画框条（按素材定）、插条、对比卡／原话卡／时间线、政策原文页、每镜手写 why |
| 素材 | `stock.py auto` 自动取 → 看一张审片表判五问 | 每镜看候选图挑（`stock.py plan`），或同样 auto＋审片 |
| 审 | qa | qa＋评审子代理 |
| 硬检查 | 审片理由、数字核对、标题 | 另加 build 按片长查表达层（见 SKILL.md §3.5） |

列举、序号、问题清单由 `beats.py` 识别：不只认「第一／第二」，「是三件事」「有几件必须问清」「一串问句」都算（10-30：76 号片的「三件事」「五个问题」上一版极简档一处都没认出来，147 秒里 129 秒是人脸）。

## 成本（2026-10-29 实测，10-30 改规则后仍成立）
| 环节 | 完整版 | 极简档 | 省在哪 |
|---|---|---|---|
| 判定 | 底稿＋人工升级（最大的 token 项） | 底稿＋读顺文字 | 省掉大头 |
| B-roll 挑选 | 每镜一张候选图、人看图挑 | 自动取＋一张审片总图 | 少看 N 张图 |
| 渲染 | 小窗／分带要同时解码两三路视频 | 只有满幅，最快 | 省渲染 |

## 流程（极简档）
`ingest → 校对 → numcheck → analyze → trim → beats.py` →
`python3 scripts/lite_plan.py <工程> --series … --episode …` → 改 `_待改` →
`python3 scripts/stock.py <工程> auto --decompose decompose_lite.json` → 审片（下节）→
`build.py <工程> --decompose decompose_lite.json` → `render.py --stills` → `qa.py`。

## 审片（自动素材必过）
`stock.py auto` 取完出 `broll/stock/auto_review.jpg`：每条一行 **[前一个画面][素材三帧][后一个画面]**，写着原话、检索词和自动提醒（亮度差 >55、冷暖差 >45、和上一条同检索词、几乎一样＝重复素材）。
Agent 看图逐条判五问，填 `auto_review.json` 的 `verdict`（keep／replace／drop）和 `reason`：
1. **贴题**：画面主体和这句话说的东西直接相关吗？
2. **地域**：讲内地／香港的事，有外国国旗、外国政府楼、外文招牌吗？有就 replace
3. **前后接**：和前后画面亮度、冷暖突兀吗？（自动提醒只是提示，蓝天接室内差 40 上下正常）
4. **画面里的字和脸**：有可读的无关文字、陌生人大正脸吗？
5. **重复**：和别的镜头是同一条或几乎一样吗？

**reason 要写画面主体**（「中环中银大厦白天外立面，对应『二级市场照旧』」），≥8 字；写「通过／复审通过」build 会停（10-30：DeepSeek 一次把 6 条全写「复审通过」，两条刚换过没看图）。
replace 的在 decompose 该镜写新的 `q`（**列表**，按优先级），然后 `stock.py <工程> redo --decompose decompose_lite.json`：被否的素材进 `rejected` 不再选；改过 `q` 但还没判 keep 的也会一起重取；drop 的镜头删掉。重复到全部 keep。
检索词：地域＋实物＋状态（`hong kong` 打头）；没有能拍的实物就 drop 这条、让清单卡或金银整行扛，别硬配「文件、清单、钥匙」这类泛化画面。

## 已知局限
- 审片依赖看图判断：检索词再准也会偶尔取到不贴题的，这一步不能省。
- 自动摘的清单文字常常截半句（「能给客户配什么工」），`_待改` 里列了，必须读一遍改顺。
